# Проект 2. Cashback Merge

Мини-игра в духе 2048 на поле `4x4`. На поле появляются плитки с кэшбэком,
две одинаковые объединяются в следующую:

```text
1% + 1% = 2%    2% + 2% = 4%    ...    16% + 16% = 32%
```

У игрока ограниченное число ходов, цель — собрать максимальный кэшбэк.

Но у проекта есть второй, продуктовый слой. По итоговой плитке начисляется
награда, и эта награда стоит компании денег. Поэтому максимальную награду
должна получать ограниченная доля игроков — например, не больше `20%`.
Проверяется это симуляцией на тысячах «игроков» до запуска акции.

Задание разбито на три merge request'а. Делай их по очереди.

## Быстрый старт

```bash
./gradlew run     # запустить программу
./gradlew check   # тесты и линтеры — ровно то, что проверяет CI
./gradlew run --args="--config-source CONFIG_DIRECTORY --config campaign.example.json --seed 42"   # симуляция
```

Нужен **JDK 25 или новее**. Gradle ставить не нужно — в проекте лежит `gradlew`,
он скачает нужную версию сам.

Свой код складывай в `src/main/java/academy/cashbackmerge/`.

Загрузка JSON-конфига кампании реализована с помощью интерфейса `ConfigLoader`, который реализуют классы `ConfigDirectoryConfigLoader`, `ClasspathConfigLoader` и `StringConfigLoader`.

Парсинг конфигурации кампании реализован в классе `GameSettingsParser`, который использует Jackson для десериализации JSON. Валидация конфигурации проводится в классе `GameSettings`, который проверяет корректность полей и соблюдение инвариантов.

Поле игры реализовано в классе `Field`, который использует двумерный массив для хранения состояния поля.

Добавление рандомной плитки на поле реализовано в классе `RandomCashbackGenerator`, который использует `Random` с заданным seed для воспроизводимого выбора позиции и значения плитки.

Инициализация игры производится в классе `GameService`, который создает объект `GameSession`, который хранит состояние игры.

Парсинг аргументов командной строки реализован с помощью библиотеки `picocli` в классе `Main`, который запускает программу с заданными параметрами в зависимости от переданных аргументов.


Роль движка игры выполняет класс `GameEngine`, который отвечает за слияние плиток, генерацию новых плиток и изменение состояния сессии.

Слияние поля по направлению реализован в классе `MoveProcessor`, который отвечает за логику обработки строк и столбцов в зависимости от направления движения. `MoveProcessor` использует один и тот же алгоритм для всех направлений, применяя повороты поля для универсальности обработки.

Логика слияния плиток реализована в классе `LineProcessor`, который обрабатывает строку и столбец и возвращает объект класса `LineProcessorResult`, в котором содержатся результат слияния и количество очков.
